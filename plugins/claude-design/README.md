# Claude Design for Codex

This Codex plugin connects to Anthropic's remote Claude Design MCP through a
local stdio bridge.

## Why the bridge is required

Anthropic's dedicated Claude Design OAuth client uses a manual-code callback.
Codex's standard remote-MCP login instead supplies a localhost callback, which
Anthropic currently rejects as `Invalid request format`. The bridge performs
the documented Design flow and forwards authenticated MCP traffic locally.

## First-use authentication

The first Claude Design request opens a local browser helper. Select
**Authorise with Claude**, approve Claude Design in the new tab, copy the
short-lived `CODE#STATE` value Claude displays, and paste it back into the
local helper tab. The pending Codex request then continues normally.

The helper binds only to `127.0.0.1`, keeps the OAuth verifier on the local
machine, and shuts down after authentication or ten minutes. Do not paste the
code into chat.

Future plugin uses start normally and refresh the access token locally while
the refresh token remains valid.

Credentials are stored outside the plugin with owner-only permissions at:

```text
~/.config/codex-claude-design/credentials.json
```

The plugin never prints access or refresh tokens. They are sent only to
Anthropic endpoints, and the access token is passed to the MCP bridge through a
child-process environment variable rather than a command-line argument.

The bridge pins `mcp-remote` to version `0.1.37`. Its OAuth implementation is
adapted from `erdnj/claude-design-mcp` at commit
`5e50b691df5259668cf80fcd41766d4da17a80ce`, under the MIT licence. See
`THIRD_PARTY_NOTICES.md`.
