# Claude Design for Codex

This Codex plugin connects to Anthropic's remote Claude Design MCP through a
local stdio bridge.

Explicit Claude Design requests stay on this connector. The bridge adds exact
raw `download_file_to_local` and complete `export_project_to_local` tools so
binary assets and standalone local bundles do not require browser fallback.

When design-system context applies, the bundled skill tells Codex to inspect
the capabilities that are actually present and use the strongest suitable
layer: templates, components, tokens, styles, assets, or written guidance. It
does not treat binding, copying, or loading a design system as proof that the
deliverable uses it.

For native-agent delegation, the skill can give a complete execution brief to
an authenticated Claude Code agent running the Design MCP bridge. If Claude
Code is unavailable or logged out, it writes `CODEX_HANDOFF.md` into the
project and directs the user to execute it from a fresh Claude Design chat.
Synced chats created by `put_conversation` are read-only in the web app, so the
skill treats them only as audit transcripts and never as an execution path.

## Why the bridge is required

Anthropic's dedicated Claude Design OAuth client uses a manual-code callback.
Codex's standard remote-MCP login instead supplies a localhost callback, which
Anthropic currently rejects as `Invalid request format`. The bridge performs
the documented Design flow and forwards authenticated MCP traffic locally.

## First-use authentication

The first Claude Design request opens a local browser helper. Select
**Authorise with Claude**, approve Claude Design in the new tab, copy the
short-lived `CODE#STATE` value Claude displays, and paste it back into the
local helper tab. The pending Codex request then continues normally.

The helper binds only to `127.0.0.1`, keeps the OAuth verifier on the local
machine, and shuts down after authentication or ten minutes. Do not paste the
code into chat.

Future plugin uses start normally and refresh the access token locally while
the refresh token remains valid.

## Multiple Claude accounts

Connect named accounts with `claude-design-codex login --account <name>`. The
local browser helper lets the user confirm or edit that local profile name
before saving credentials. It also lists existing profiles and offers a
two-step removal flow that deletes only the selected local credential file.
The bridge can route an individual tool call with its optional `account` field
or change the active route for the running Codex session with
`set_session_account`.

Set the persistent default with `claude-design-codex default <name>`. To pin a
Codex process to one account, launch it with
`CODEX_CLAUDE_DESIGN_ACCOUNT=<name>`; a pinned process does not expose account
switching. Manual MCP configurations can use `server --account <name>` for the
same pin.

Credentials are stored outside the plugin with owner-only permissions at:

```text
~/.config/codex-claude-design/accounts/<account>.json
```

The old `credentials.json` location remains the legacy `default` account.

The plugin never prints access or refresh tokens or sends local account labels
to Anthropic. Tokens are sent only to Anthropic endpoints, and each account's
access token is passed to its MCP bridge through a child-process environment
variable rather than a command-line argument.

The bridge pins `mcp-remote` to version `0.1.37`. Its OAuth implementation is
adapted from `erdnj/claude-design-mcp` at commit
`5e50b691df5259668cf80fcd41766d4da17a80ce`, under the MIT licence. See
